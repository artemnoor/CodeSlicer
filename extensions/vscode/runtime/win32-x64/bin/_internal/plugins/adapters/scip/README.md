# SCIP Semantic Index adapter

This optional adapter is local-only. CodeSlicer imports an index only after an
explicit user action; it never starts a SCIP indexer, installs SCIP tooling, or
uploads an index or project data.

The importer accepts real binary SCIP protobuf files using a small
dependency-free decoder for the standard `Index`, `Metadata`, `Document`,
`Occurrence`, `SymbolInformation`, `Relationship`, and typed range messages.
It also accepts the documented local interchange form
`CodeSlicerScipInterchange/v1`, stored in a file with a `.scip` name, for
deterministic fixtures and backward compatibility. Binary parsing is limited
to the semantic fields CodeSlicer needs; unknown protobuf fields are skipped
for forward compatibility.

Imported artifacts are copied only to `.codeslicer/artifacts/scip/index.scip`
and state is kept in `.codeslicer/adapters/scip.json`. The canonical
`.impact_engine` graph is never modified. Fresh exact mappings can confirm
semantic evidence; stale, ambiguous, and name-only mappings remain
stale/unresolved and never raise Review ranking or risk. Fresh confirmation
requires an exact source file + complete definition range + kind match, or a
previously persisted stable semantic ID; file + name + kind is never a
confirmed mapping.

`Metadata.project_root` is interpreted as a URI, as required by SCIP. Local
`file://` roots are checked against the selected project; non-local or missing
roots are reported as unverified.

## Parser versus interoperability

These are separate quality gates:

| Gate | Meaning | Current test |
|---|---|---|
| Protobuf parser passed | CodeSlicer decoded the standard SCIP wire format, including typed ranges, metadata, occurrences and relationships | Always covered by local deterministic fixtures |
| External-indexer interoperability verified | A binary artifact generated by the named independent indexer passed CodeSlicer expectations and official `scip lint` | Opt-in only; requires materialized golden artifacts and a user-installed `scip` CLI |

The reproducible source projects and manifests are in
`tests/fixtures/scip/golden/`. This checkout records the recipes but does not
pretend that hand-authored protobuf fixtures were generated by official
indexers. Run `pytest -m scip_interop` or
`impact-engine adapters verify-scip` only after explicitly generating the
artifacts. Missing tools or artifacts are skipped with a diagnostic; no npm,
NuGet, Docker, download, upload, or indexer subprocess is started by an
ordinary CodeSlicer import/review.

The recipes follow the upstream [SCIP schema](https://github.com/scip-code/scip/blob/main/scip.proto),
the [scip-typescript README](https://github.com/sourcegraph/scip-typescript),
the [scip-python package](https://www.npmjs.com/package/@sourcegraph/scip-python),
and the [scip-dotnet package instructions](https://www.nuget.org/packages/scip-dotnet/0.2.14).

After an explicit generation, set the manifest status to `materialized` and
record the artifact SHA-256 in the matching manifest. The verifier then checks parser metadata/document paths/typed ranges,
expected definitions/references/implementations, and invokes `scip lint` when
that official CLI is already available locally.
